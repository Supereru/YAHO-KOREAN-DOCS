# 한국어 용어집

일반 문서 작성, 화면 안내(UI), 소프트웨어, 데이터, 인공지능 설명에서 사용하는 핵심 용어와 표현 140개입니다. 모든 항목은 문맥을 먼저 확인한 뒤 적용하며, 코드, 화면의 실제 표시 이름, 직접 인용문 및 해당 기술 분야에서 정의한 전문용어는 원형을 우선 보존합니다.

- **근거 상태 안내:** ‘자료 확인’은 링크된 공식 자료에서 대응어나 기본 개념을 확인했다는 뜻이며, 해당 기관이 이 표의 세부 조건과 예시까지 승인했다는 의미는 아닙니다. ‘자체 제안’은 실무 명료성을 위해 설계한 자체 기준이므로 국가 공인 순화어나 표준 용어로 제시하지 않습니다.
- **공통 적용 조건:** 원문의 뜻, 범위, 조건, 요구 수준을 온전히 보존할 수 있을 때만 표현을 바꿉니다. 권장 표현에 빗금(`/`)으로 나열된 대안은 문맥에 맞는 것 하나만 골라 쓰며, 실제 문장에서는 중간점(가운뎃점)이나 빗금 대신 쉼표(,), '와/과', '및', '또는'을 사용합니다. 원문만으로 정확한 뜻을 확정할 수 없으면 임의로 고치지 않고 ‘확인 필요’로 남깁니다.

| T113 | 정확도 | [산식 및 지표 명시] 정확도 | 분류 모델의 `Accuracy` 등 구체적으로 어떤 평가 지표인지 밝히며, 정밀도, 재현율 및 일상어의 ‘정확성’과 구분합니다. | 자체 제안 |
| T114 | 정밀도 | [분야 명시] 정밀도 | 분류 모델의 `Precision`인지 계측 장비의 정밀도인지 구분하며, 일상어인 ‘정확도’로 바꾸지 않습니다. | 자체 제안 |
| T115 | 재현율 | 재현율 | 정보 검색 및 분류 모델에서 실제 정답 중 찾아낸 비율(`Recall`)을 뜻할 때 유지하며, 과학 실험의 재현성(Reproducibility)과 구분합니다. | 자체 제안 |

## 5. 문장 표현과 요구 수준 (25개)

문장을 짧게 줄인 결과가 언제나 더 정확한 것은 아니므로, 원문이 이미 명확하다면 그대로 유지합니다.

| ID | 입력 표현 | 권장 표현 또는 처리 | 적용 조건과 예외 | 근거 |
| --- | --- | --- | --- | --- |
| T116 | 확인을 수행하다 | 확인하다 | 고유 작업명이나 직접 인용이 아닌 일반 서술문에서 불필요한 명사형을 동사로 줄입니다. | 자체 제안 |
| T117 | 변경을 진행하다 | 변경하다 / 변경 중이다 | 앞으로 수행할 동작이면 ‘변경하다’, 현재 진행 상태이면 ‘변경 중이다’로 시제와 상태를 살려 고칩니다. | 자체 제안 |
| T118 | 삭제를 실시하다 | 삭제하다 | 일반적인 삭제 동작을 지시할 때 간결하게 줄이며, 삭제 대상 범위와 결과 조건은 그대로 보존합니다. | 자체 제안 |
| T119 | 사용이 가능하다 | 사용할 수 있다 / 사용해도 된다 | 시스템 기능과 능력을 뜻하면 ‘사용할 수 있다’, 정책상 허용을 뜻하면 ‘사용해도 된다’로 구분합니다. | 자체 제안 |
| T120 | ~을 필요로 하다 | ~이 필요하다 | 문장의 조사(‘~을’ → ‘~이/가’)와 서술어 호응을 함께 자연스럽게 다듬을 수 있을 때 적용하며, 단순 단어 치환은 피합니다. | 자체 제안 |
| T121 | ~에 대한 확인 | ~을 확인 | 제목이 아닌 일반 동작 문장에서 번역투 조사(‘~에 대한’)를 목적격 조사(‘~을/를’)로 자연스럽게 고칩니다. | 자체 제안 |
| T122 | ~의 경우 | ~이면 / ~에서는 | 가정이나 조건이면 ‘~이면’, 특정 상황이나 대상 범위이면 ‘~에서는’으로 풀며, 조건이 아닌 문장을 조건문으로 바꾸지 않습니다. | 자체 제안 |
| T123 | ~에 의하여 | [주체 명시 또는 유지] | 실제 동작 주체가 알려져 있고 중요할 때만 능동문으로 바꾸며, 법령이나 규정 등 근거를 뜻할 때는 문맥에 맞게 유지합니다. | 자체 제안 |
| T124 | ~되어지다 | ~되다 | ‘만들어지다’ 등을 제외한 불필요한 이중 피동 표현일 때 단일 피동이나 능동 표현으로 바로잡습니다. | 자체 제안 |
| T125 | 해당 / 상기 / 전술한 | [실제 대상 이름 명시] | 앞에서 언급한 대상이 여러 개여서 지시 대상이 모호할 때 실제 이름을 적습니다(대상이 명확하면 자연스러운 지시어 유지 가능). | 자체 제안 |
| T126 | 적절히 / 충분히 | [기준 명시 또는 확인 필요] | 원문에 구체적 수치나 기준이 있으면 함께 적고, 기준이 없으면 임의로 숫자나 횟수를 지어내지 않고 확인 사항으로 남깁니다. | 자체 제안 |
| T127 | 신속히 / 조속히 | [기한 명시 또는 원문 유지] | 원문에 구체적인 기한이 있을 때만 기한을 적으며, 근거 없이 ‘즉시’로 요구 수준을 강화하지 않습니다. | 자체 제안 |
| T128 | 일반적으로 / 대체로 | [필요시 유지] | 설명이나 주장의 성립 범위를 제한하는 필수 한정어라면 삭제하지 않으며, 단순한 습관성 군더더기일 때만 덜어냅니다. | 자체 제안 |
| T129 | 등 / 기타 | [범위 명시 또는 유지] | 예시를 나열한 열린 목록인지 대상이 확정된 닫힌 목록인지 확인하며, ‘등’을 임의로 지워 전체 목록인 것처럼 바꾸지 않습니다. | 자체 제안 |
| T130 | 및 / 와 / 과 | [모두 포함 관계 명시] | 나열된 항목이 논리적으로 모두 필요한(AND) 관계일 때 쓰며, 중간점(가운뎃점)이나 ‘또는’으로 바꾸지 않습니다. | 자체 제안 |
| T131 | 또는 | [포괄 및 배타 여부 확인] | 하나 이상 선택(포괄적 OR)인지 둘 중 하나만 선택(배타적 XOR)인지 확인하며, 중간점(가운뎃점)으로 모호하게 표기된 원문은 뜻을 확인해 풀어서 씁니다. | 자체 제안 |

| T133 | 권고 / 권장 | 권장합니다 | 선택 가능한 권장 사항임을 유지하며, 필수 수행 의무(‘해야 합니다’)로 바꾸지 않습니다. | 자체 제안 |

## 공식 자료 확인 표현과 자체 제안의 관계

공식 기관의 순화어나 표제어라도 전문 기술 분야에 적용할 때는 문맥상 의미가 부합하는지 다시 확인해야 합니다. 예를 들어 국립국어원 자료에는 ‘인터페이스’의 다듬은 말로 ‘접속 장치’가 등재되어 있지만, 소프트웨어의 UI나 API까지 ‘접속 장치’로 바꾸면 기술적 의미가 왜곡됩니다. 따라서 이 용어집에서는 T055(인터페이스)의 일괄 치환을 금지하고, T057(API)은 원래 기술 명칭을 유지하도록 설계했습니다 ([국립국어원 항목][S05], [TTA API 항목][S07]).

또한 TTA 정보통신용어사전의 정의를 바탕으로 T084(인증)와 T085(인가)를 각각 ‘신원 확인’과 ‘자원 이용 권한 부여’로 명확히 분리했으며, T065(백업)와 T068(아카이브) 역시 ‘사고 대비 복구용 사본’과 ‘장기 기록 보관’이라는 목적 차이를 유지하도록 구성했습니다 ([TTA 인가][S06], [TTA 디지털 아카이브][S08]).

이 용어집은 작성자와 검토자가 문맥의 뜻을 정확히 판단하도록 돕는 기준표입니다. 따라서 단순 문자열 찾기 및 바꾸기(자동 치환기)의 금지어 목록으로 사용해서는 안 되며, 한국어의 조사와 어미 활용을 무시한 부분 문자열 치환도 적용하지 않습니다.
