# 명확한 한국어 기술 문서

이 스킬은 함께 제공된 세 자료를 한 세트로 적용한다. 공식 ASD-STE100 한국어판이나 인증 기준으로 소개하지 않는다.

## 자료 읽기

작업을 시작할 때 아래 세 파일의 본문을 읽는다. 이 경로는 이 SKILL.md가 있는 폴더를 기준으로 해석한다. 사용자가 처음 제공했던 컴퓨터의 경로에 의존하지 않는다.

1. [적용 지침](references/guidelines.txt): 핵심 규칙 20개, 예외 처리와 기본 출력 형식.
2. [규칙집](references/rules.md): R01부터 R36까지의 규칙, 예시와 대조 절차.
3. [용어집](references/glossary.md): T001부터 T140까지의 분야, 의미, 적용 조건과 예외.

긴 파일의 읽기 결과가 잘렸다면 나머지 부분도 나누어 읽는다. 같은 작업에서 이미 읽은 내용은 재사용한다. 자료를 읽을 수 없으면 읽었다고 주장하지 않는다. 적용 지침만 읽을 수 있을 때는 그 안의 핵심 규칙 20개만 적용했다고 밝힌다. 적용 지침도 읽을 수 없다면 누락 파일을 알리고 전체 세트를 적용했다고 주장하지 않는다.

참고 자료에 적힌 출처 확인일과 확인 범위는 자료 작성자의 기록이다. 출처 검증을 요청받으면 문서의 실제 링크와 확인 범위를 바탕으로 확인하며, 기존 문서에 적힌 확인일을 자신의 확인일로 바꾸지 않는다.

## 작업 유형

요청이 어느 유형인지 먼저 정한다. 유형이 불분명하면 다듬기로 진행한다.

| 유형 | 요청 예 | 결과물 |
| --- | --- | --- |
| 다듬기 | "이 문서를 다듬어 줘" | 수정한 전체 문서, 핵심 수정 이유, 확인 필요 사항 |
| 새로 작성 | "이 사실로 안내문을 써 줘" | 제공되거나 확인된 사실만 사용한 새 문서, 확인 필요 사항 |
| 용어 통일 | "용어만 맞춰 줘" | 용어만 고친 문서와 대표 용어 목록. 문장 구조는 고치지 않는다 |
| 검토 | "고치지 말고 문제만 알려 줘" | 위치, 문제, 수정 제안을 적은 목록. 원문은 고치지 않는다 |

## 적용 방법

- 사용자 지정 문체, 대상 독자와 문서 목적을 우선한다. 독자가 불분명하면 일반 기술 설명문을 기준으로 진행한다.
- 편집 범위 안에서 문장을 다듬는다. 사실, 수치, 단위, 조건, 예외, 부정, 순서, 동시성, 책임 주체, 의무 수준과 불확실성을 보존한다. 새 문서는 제공되거나 확인된 사실을 바탕으로 작성한다.
- 직접 인용, 코드, 명령어, 경로, 파일명, 제품명, 식별자와 실제 화면 표시 이름은 보호한다. 나열 관계를 풀어 쓸 때도 보호 구간의 중간점이나 빗금을 임의로 고치지 않는다.
- 원문의 문서 형식을 유지한다. 제목 단계, 표의 행과 열, 목록 번호, 링크, 각주, 코드 블록을 임의로 합치거나 지우지 않는다. 문단을 번호 목록이나 표로 바꿀 때는 규칙집의 조건(R19, R34)에 맞는 경우로 한정한다.
- 용어는 분야와 의미를 확인한 뒤 조건에 맞는 항목만 적용한다. 단순 문자열 치환이나 일괄 외래어 순화를 하지 않는다. 인증과 인가, 저장과 적용, 백업과 동기화 등 서로 다른 개념을 합치지 않는다.
- 뜻이 모호한 표현은 원문을 유지하고 필요한 확인 사항을 적는다. 주체, 오류 원인, 해결 조작, 기한이나 안전 등급을 추측해 만들지 않는다.
- 다듬은 뒤 원문과 대조한다. 특히 경계값, AND와 OR, 금지와 가능, 예정과 완료, 동시 조작이 달라지지 않았는지 확인한다.

## 긴 문서

- 문서 전체를 먼저 읽고 대표 용어와 문체를 정한 뒤 절 단위로 다듬는다. 뒤 절에서 같은 개념에 다른 이름을 쓰지 않는다.
- 분량 때문에 일부 절만 처리했다면 처리한 범위와 남은 범위를 밝힌다. 처리하지 않은 절을 요약하거나 생략해서 전체 결과처럼 제시하지 않는다.
- 사용자가 일부만 지정했다면 그 범위만 고친다. 범위 밖에서 발견한 문제는 고치지 않고 확인 필요 사항으로 알린다.

## 결과 제시

사용자가 요청한 형식을 우선한다. 기본은 완성 문서를 먼저 제시하고, 중요한 수정 이유와 확인 필요 사항만 짧게 덧붙인다. 문장마다 규칙 번호를 달지 않는다. 변경 전후 비교표는 요청받았을 때 제공한다. 고칠 곳이 없는 문장은 그대로 두며, 수정 실적을 만들려고 표현을 바꾸지 않는다. 표현 검토 결과를 전문 기술 검증이나 공식 인증으로 확대하지 않는다.
